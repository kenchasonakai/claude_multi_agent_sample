# 報告フォーマット

PdM がユーザーに報告するときのフォーマット定義。
各フェーズで承認を求めるときは、ユーザーが判断に必要な情報を過不足なく提示する。
詳細は `.agent-docs/` のファイルを参照してもらう。

---

## 要件確認（承認を求める）

```
## 要件確認

### やりたいこと
（1-2文で要約）

### スコープ
- やること: ...
- やらないこと: ...

### 前提・制約
- ...

この内容で進めてよいですか？
```

---

## デザイン報告（承認を求める）

```
## 画面デザイン

### 作成した画面
| # | 画面名 | ファイル |
|---|--------|---------|
| 1 | ... | .agent-docs/features/{NNN}/designs/{name}.pen |

### デザイン方針
（どういう方針でデザインしたか、2-3文）

### 画面構成
- （画面1）: ...の画面。...のコンポーネントを配置
- （画面2）: ...

（ここにスクリーンショットを提示する。Pencil の get_screenshot で取得）

修正したい箇所があればお伝えください。
このデザインで進めてよいですか？
```

---

## 設計報告（承認を求める）

```
## 設計方針

### 概要
（どういうアプローチで作るか、2-3文）

### 主な技術判断
- （判断1）: 理由
- （判断2）: 理由

### 影響範囲
- 変更ファイル: ...
- 新規ファイル: ...

### リスク
- （あれば）

詳細: .agent-docs/features/{NNN}/design.md

この方針で進めてよいですか？
```

---

## タスク分解報告（承認を求める）

```
## タスク分解

| # | タスク | PR名 | 依存 | 推定差分 |
|---|--------|------|------|----------|
| 1 | ... | feat/xxx-step1 | なし | ~50行 |
| 2 | ... | feat/xxx-step2 | #1 | ~120行 |

### 実行計画
- 並列: ...
- 逐次: ...

詳細: .agent-docs/features/{NNN}/tasks.md

この計画で実装を開始してよいですか？
```

---

## 実装進捗（都度報告）

```
## 進捗報告

| # | タスク | 担当 | 状態 |
|---|--------|------|------|
| 1 | ... | engineer-1 | 完了 |
| 2 | ... | engineer-1 | 作業中 |
| 3 | ... | engineer-2 | 作業中 |

### 完了したもの
- #1: PR #{N} 作成済み

### 問題・相談
- （あれば）
```

---

## セキュリティレビュー結果

```
## セキュリティレビュー

### 総合判定: 問題なし / 軽微な指摘あり / ブロッカーあり

### 指摘事項
| 重要度 | 箇所 | 内容 | 対応 |
|--------|------|------|------|
| 軽微 | src/api/upload.ts:23 | 入力サイズ未検証 | 修正済み |

詳細: .agent-docs/features/{NNN}/reviews/{pr-name}.md
```

---

## 完了報告

```
## 完了報告

### 作成した PR
| # | PR | 状態 |
|---|-----|------|
| 1 | feat/xxx-step1 #{N} | マージ待ち |
| 2 | feat/xxx-step2 #{N} | マージ待ち |

### 変更サマリ
（何がどう変わったか、2-3文）

### テスト結果
- 全テスト通過

PR をレビューしてください。
```
